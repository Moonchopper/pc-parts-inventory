*Written by the PM for Austin, 2026-09-05, after the §7 integration gate passed on `feat/m0-seed`. Playbook §6
gate 6 and §10: automated gates don't catch feel. Please do this pass before anything is pushed.*

**Branch:** `feat/m0-seed` in `d:\pc-parts-inventory`. Nothing has been pushed; `main` does not exist yet.
**Toolchain:** Node 22.14.0, Docker 29.6.1, Windows PowerShell 5.1.
**Time:** about 30 minutes for §1–§6; §1 needs a second Windows machine.

## 0. Before you start

```powershell
pnpm install --frozen-lockfile
pnpm build
```

- **If `pnpm` is not found in a fresh terminal**, re-run the bootstrap — `corepack enable pnpm` **fails on this box**
  (`EPERM`, `D:\nodejs` is not user-writable), so use:
  `corepack enable --install-directory C:\Users\austi\bin pnpm`
- `[ERR_PNPM_IGNORED_BUILDS]` during install is a warning, not a failure — the exit code is 0.
- **Port 3000 footgun:** VS Code sometimes squats `127.0.0.1:3000`. Node then binds with **no error** and every
  request hangs forever. If the API seems dead, run `netstat -ano | findstr :3000` before blaming the code.

**What "correct" looks like in numbers.** The gate run against your MOONPC scan produced: 9 products, 10 parts,
1 build, 4 quotes, `Paid $1,800.00`, `Now $1,678.96`, `Δ −$236.03 (−13.1%)` over 4 comparable parts. Your numbers
will differ once you set your own prices; the shapes should not.

## 1. Scan a **second** machine and watch it become a build

Pillar 1 — capture is automated, not typed. MOONPC is already the committed fixture; this proves the scanner
works on hardware nobody developed against.

1. `pnpm dev` → API on `http://localhost:3000` (Scalar docs at `/api/docs`), web on `http://localhost:5173`.
2. Copy `tools\scanner\` to the second machine and run:
   ```powershell
   powershell -NoProfile -File tools\scanner\scan.ps1 -OutFile scan.json -Pretty
   ```
   **Look for:** `schemaVersion: 1`; the right hostname; one component per real part; manufacturer/model that read
   like a human wrote them (no `Corporation`, no `(TM)`, no trailing spaces, and the model must **not** repeat the
   manufacturer — `Ryzen 7 9800X3D`, not `AMD Ryzen 7 9800X3D`); serials present where the hardware exposes them
   and `null` — never `"Default string"` — where it does not.
   **Edge case:** try a laptop or a headless box. The scanner must warn and skip the monitor category, not abort.
3. Send it in (from that machine, pointing at your dev box):
   ```powershell
   powershell -NoProfile -File tools\scanner\scan.ps1 -ApiUrl http://<devbox>:3000
   ```
   **Look for:** HTTP 201 and a printed summary with `productsCreated` / `partsCreated` / `buildId`.
4. Open `http://localhost:5173/builds`. **Look for:** a new build named after that machine's hostname.
5. **Re-run the same scan** and refresh. **Look for:** *no* duplicate build, *no* duplicate parts, and a **200**
   (replay) rather than a 201. That's D8, idempotent import.
6. **Edge case:** unplug a monitor, re-scan, open `/` (inventory). **Look for:** the removed part still listed with
   status `on_shelf` — never deleted.

## 2. Paid-vs-now: the number this milestone exists for

Pillar 2. Nothing sets a cost basis automatically in M0 (order-history import is M1), so you set one by hand.

1. On `/` (inventory), pick a part that shows a **current** price. Note its row.
2. Set what you paid — inline on the inventory row if the form is there, otherwise from `/api/docs`:
   `PATCH /api/v1/parts/{id}` with `{"acquiredPriceCents": 55000}` (**integer cents** — 55000 is $550.00).
3. Reload `/builds/{id}`. **Look for:** `Paid` moves by exactly what you entered, and `Δ` moves with it.
   **Exact to the cent** — money is integer minor units, so a one-cent drift is a real bug.
4. **The thing most likely to look wrong, and isn't:** `Δ` is **not** `Paid − Now`. The three numbers cover
   different sets of parts, and the caption underneath says so — *"Now covers 5 of 10 parts · delta over the 4
   parts with both a cost basis and a price"*. `Paid` spans parts you priced, `Now` spans parts with a quote, and
   `Δ` compares only the parts that have **both**. If those three ever do line up arithmetically it's a
   coincidence, not a rule. Tell me if the caption doesn't make that land.
5. **Edge case:** clear an acquired price entirely. **Look for:** the row shows `—`, not `$0.00`, and it drops out
   of the Δ set rather than counting as a free part.

## 3. Share a build as a URL, and paste it into Discord

Pillar 3 — the PCPartPicker bar.

1. From `/builds`, open a build and copy `http://localhost:5173/b/<slug>`.
2. Open it. **Look for:** name, one row per part in **PC-part order** (CPU, motherboard, memory, storage, video
   card, monitor…), prices, and the Paid/Now/Δ block. **No serial numbers, no notes, no "acquired from", no owner
   name.** A serial on this page is a stop-the-line bug.
3. **No-JS check:** DevTools → Settings → Debugger → "Disable JavaScript", reload. **Look for:** the page still
   renders completely. The "copy Markdown" button becoming a plain link is intended.
4. **Unfurl check:** paste the URL into a Discord DM to yourself.
   - `localhost` will **not** unfurl from Discord's servers. Either run the compose stack behind a tunnel, or open
     `http://localhost:5173/api/v1/share/<slug>/card.png` directly and judge the image. **Say which you did.**
   - **Look at the card:** name not clipped; up to 8 rows plus "+N more"; per-item prices or `—`; the
     Paid/Now/Δ footer with Δ coloured; the two-line caption fully visible with space beneath it.
5. **Edge case — private:** `PATCH /api/v1/builds/{id}` with `{"visibility":"private"}` from `/api/docs`, then
   reload `/b/<slug>`. **Look for:** a 404 page — not an error dump, not the build. Set it back to `unlisted`.

## 4. "Copy Markdown" → paste into Reddit

1. On the share page, click **Copy Markdown**.
2. Paste into a Reddit comment box and hit **Preview** (any Markdown previewer works).
3. **Look for:** a clean `Type | Item | Price` table, one row per part, readable type names ("Video Card", not
   `gpu`), the Paid/Now/Δ rows, the italic caption, and the "Generated by" footer. Nothing should break the table.
4. **Edge case:** a build with one item, and a part whose model contains a `|`.

## 5. Manual entry and build editing

These endpoints exist as of this milestone; they're the fallback when capture can't reach something.

1. `/builds/{id}` → **add a part** to a build, then **remove** it. Works with JS disabled (plain form posts).
2. **Edge case:** add a part that's already in **another** build. **Look for:** a readable message naming the
   build it's already in — not a raw 502.
3. **Edge case:** delete a part that's in a build via `/api/docs` (`DELETE /api/v1/parts/{id}`). **Look for:** a
   **409** refusing it; retry with `?force=1` and it succeeds.
4. `DELETE /api/v1/builds/{id}` on a throwaway build. **Look for:** the build is gone and **its parts still exist**,
   now `on_shelf`. Deleting a build must never delete hardware you own.

## 6. `docker compose up` — the deployment story

Stop `pnpm dev` first so the ports are free.

```powershell
docker compose down -v      # start from nothing — removes the pcpi-data volume
docker compose up --build
```

1. **Look for:** both containers start, `api` reports healthy, and the log shows migrations running against an
   empty database.
2. Import the fixture:
   ```powershell
   curl.exe -s -X POST http://localhost:3000/api/v1/imports/scans -H "Content-Type: application/json" --data-binary "@tools/scanner/fixtures/MOONPC.redacted.json"
   ```
3. Open `http://localhost:5173/` and `http://localhost:5173/b/<slug>`. **Look for:** the same pages as dev mode.
4. **The unfurl path specifically** — this is what Discord fetches:
   ```powershell
   curl.exe -s -o card.png -w "%{http_code} %{content_type}`n" http://localhost:5173/api/v1/share/<slug>/card.png
   ```
   **Look for:** `200 image/png`. Anything else means the share card won't unfurl.
5. `docker compose restart api`, reload the share page. **Look for:** the data survived — it's on a named volume.
6. `docker compose down` when finished. **Look for:** no stray node processes, no held ports.
7. *Note:* the images are large (~717 MB api, ~592 MB web). Known, deliberate for M0, with a slimming work item
   queued for M1.

## 7. What to report back

Per section: what you did, what you saw, and anything that felt wrong even if nothing errored. Especially:

- Any serial, note, "acquired from" or owner name on a share page, in the Markdown, or on the card.
- Any money figure off by a cent, or a Δ whose sign looks wrong.
- Whether the **Paid / Now / Δ caption** actually explains why the three don't add up — that wording is new and
  you're the first person outside the build to read it.
- A scan that takes more than a few seconds, or reports hardware you don't have.
- Anything that looks bad at phone width, or a card that clips.
- Anything you had to guess at — that's a docs bug, and the cheapest kind to fix.

## Known limits in M0 (not bugs)

- One owner (`local`), no auth UI. `API_TOKEN` is unset in dev and compose, so mutating routes are open.
- Only the `fixture` pricing provider is active without a Best Buy key — prices are scaffolding, not market truth.
  `GET /api/v1/providers` shows `bestbuy` as `configured: false`.
- Cost basis is manual. Order-history import and barcode capture are M1.
- Builds hold owned parts only — no wishlist items (D9).
- Postgres is a compose stub, not exercised (M2). The scanner is Windows-only (M1 decides the cross-platform path).
- `POST /api/v1/jobs/run-due` returns **404** in the container by design (D10 — it's a harness/dev-only endpoint).
  Price refreshes go through `POST /api/v1/products/{id}/refresh` and the 30-second tick loop.
- CI has never run: nothing has been pushed. That's the one piece of M0's done-definition still open.
