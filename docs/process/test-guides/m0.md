## 0. Before you start

**Your dev database starts empty.** The MOONPC scan in `tools\scanner\fixtures\MOONPC.redacted.json` is a *file in
the repo* used by tests and the harness — it is **not** data in your database. Until you scan this machine (§1) or
import that file by hand (§6 step 2), `/` and `/builds` are supposed to be empty. That is not a bug.

**The dev database is disposable, and you should throw it away before this pass.** This wave changed how serials
are cleaned (a trailing `.` on the NVMe's serial is now stripped), and a part's serial *is* its identity — so rows
imported before today carry the old identity and a re-scan would create a second row for that same disk. Start
clean:

```powershell
docker compose down                      # if the containers are up, they own :3000 and :5173
Remove-Item apps\api\data\pcpi.db* -Force -ErrorAction SilentlyContinue
```

(The container's copy lives in the `pcpi-data` volume instead — `docker compose down -v` is how you reset that; §6.)

Then:

```powershell
pnpm install --frozen-lockfile
pnpm build
```

- **If `pnpm` is not found in a fresh terminal**, re-run the bootstrap — `corepack enable pnpm` **fails on this box**
  (`EPERM`, `D:\nodejs` is not user-writable), so use:
  `corepack enable --install-directory C:\Users\austi\.local\bin pnpm`
  (`.local\bin` is on the persistent user PATH; `C:\Users\austi\bin` is **not** — Git Bash adds `~/bin` on its own,
  PowerShell does not.)
- `[ERR_PNPM_IGNORED_BUILDS]` during install is a warning, not a failure — the exit code is 0.

### Start the app — this is the invocation to use

```powershell
$env:PORT = '3010'                             # API port. Not 3000: VS Code likes to squat 127.0.0.1:3000
$env:API_URL = 'http://localhost:3010'         # tells the web app where the API is
$env:PUBLIC_ORIGIN = 'http://localhost:5173'   # the origin shared links point at (D16) — see §4
pnpm dev                                       # API on :3010 (Scalar docs at /api/docs), web on http://localhost:5173
```

All three live only in that terminal — open a new one and you have to set them again. `PUBLIC_ORIGIN` is what the
Markdown export's footer link is built from; leave it out and the footer points at the API's own port (`:3010`),
which has no `/b/` page. Compose sets it for you (§6); `pnpm dev` can't guess it, so the recipe sets it here.

**Why 3010:** on Windows a socket on `127.0.0.1:3000` and one on `0.0.0.0:3000` coexist happily, and the *more
specific* one wins for `localhost` traffic. That is how VS Code (or a stale server) silently ate every request last
time. The API now checks, right after it binds, that the thing answering on its own port really is itself — if it
isn't, it prints one loud line naming the port and exits instead of pretending to work. If you ever see that line:

```powershell
netstat -ano | findstr :3010
```

…then look the PID up in Task Manager's *Details* tab.

Sanity check before you go on (**a fresh DB answers `[]` here — that's correct**):

```powershell
$api = 'http://localhost:3010/api/v1'
Invoke-RestMethod "$api/health"
$parts = Invoke-RestMethod "$api/parts"
"parts in the DB: $($parts.Count)"
```

**What "correct" looks like in numbers.** The integration gate run against your MOONPC scan produced: 9 products,
10 parts, 1 build, 4 quotes, and — once the two fixture cost bases are applied — `Paid $1,800.00`, `Now $1,678.96`,
`Δ −$236.03 (−13.1%)` over 4 comparable parts, with `Now covers 5 of 10 parts`. Your numbers will differ as soon as
you set your own prices; the *shapes* should not.

### The PowerShell 5.1 gotcha that broke last time's snippets

`Invoke-RestMethod` hands a JSON **array** to the pipeline as a *single object*, so the obvious one-liner silently
operates on the whole array instead of on each row. Two idioms are safe — **assign it to a variable first**
(preferred), or **wrap the call in parentheses**. `@( … )` around the call does **not** help:

```powershell
$parts = Invoke-RestMethod "$api/parts"     # ✅ then $parts[0], $parts.Count, $parts | Where-Object { … }
(Invoke-RestMethod "$api/parts") | Select-Object -First 1     # ✅ parentheses force enumeration
Invoke-RestMethod "$api/parts" | Select-Object -First 1       # ❌ returns the whole array
@(Invoke-RestMethod "$api/parts") | Select-Object -First 1    # ❌ also returns the whole array
```

Every snippet below already does this the safe way. Also: use **`curl.exe`**, never bare `curl` (that's an alias
for `Invoke-WebRequest` in PowerShell and takes different arguments).

## 1. Scan **this** machine, then a second one

Pillar 1 — capture is automated, not typed.

1. With `pnpm dev` running, scan and send in one step:
   ```powershell
   powershell -NoProfile -File tools\scanner\scan.ps1 -ApiUrl http://localhost:3010
   ```
   **Look for:** HTTP 201 and a printed summary with `productsCreated` / `partsCreated` / `buildId`. It also echoes
   the whole payload to the console, and prints a yellow `WARNING: MSFT_PhysicalDisk.Manufacturer blank for model
   'CT2000T700SSD5' — used a model-prefix heuristic ('Crucial')`. Both are normal: CIM genuinely leaves that field
   empty on this drive, and the scanner tells you when it inferred rather than read something.
2. Open `http://localhost:5173/builds`. **Look for:** a build named `MOONPC` (this machine's hostname), with your
   real hardware in it.
3. Open it and read the part list. **Look for:** manufacturer/model that read like a human wrote them (no
   `Corporation`, no `(TM)`, no trailing spaces, and the model must **not** repeat the manufacturer —
   `Ryzen 7 9800X3D`, not `AMD Ryzen 7 9800X3D`); category names spelled out (`Video Card`, not `gpu`); serials
   present where the hardware exposes them and `—` where it doesn't.
4. **Check the NVMe specifically** (this is the fix-up's F8):
   ```powershell
   $parts = Invoke-RestMethod "$api/parts"
   $parts | Where-Object { $_.product.category -eq 'storage' } | Select-Object id, serial, identityKey
   ```
   **Look for:** the serial ends in `…E87F_6C0C` — **no trailing dot**. A trailing `.` here means the fix regressed.
5. **Re-run the same scan** and refresh `/builds`. **Look for:** a **201** whose summary reads
   `productsCreated: 0, partsCreated: 0, productsUpdated: 9, partsUpdated: 10` (your counts will differ) and the
   same `buildId` — *no* duplicate build, *no* duplicate parts. That's D8: the import is keyed on each component's
   identity, so a re-scan **updates in place**. (A re-scan is a *new* import — its `scannedAt` differs, so its
   payload hash differs. The `200` "replay" response is for posting the **identical JSON twice**, which §6 step 2
   does; the PM confirmed both paths on this box.)
6. **Second machine** (skip if you don't have one): copy `tools\scanner\` over and run
   `powershell -NoProfile -File tools\scanner\scan.ps1 -OutFile scan.json -Pretty` to eyeball the JSON, then
   `powershell -NoProfile -File tools\scanner\scan.ps1 -ApiUrl http://<this-box>:3010` to send it in. It should
   appear as its own build. **Edge case:** a laptop or headless box — the scanner must warn and skip the monitor
   category, not abort.
7. **Edge case:** unplug a monitor, re-scan, open `/`. **Look for:** the removed part still listed with status
   `on_shelf` — never deleted.

## 2. Paid-vs-now: the number this milestone exists for

Pillar 2. Nothing sets a cost basis automatically in M0 (order-history import is M1), so you set one by hand.

**Before you set anything**, open a build page. **Look for:** `Paid —`, not `Paid $0.00`. "Nothing recorded" and
"recorded as zero" are different facts and now look different (D17).

1. Refresh a price and watch it land **without waiting 30 seconds** (D18 — this was F9):
   ```powershell
   $products = Invoke-RestMethod "$api/products"
   $p = $products[0]
   "refreshing $($p.manufacturer) $($p.model) …"
   Invoke-RestMethod -Method Post "$api/products/$($p.id)/refresh" | Out-Null
   Start-Sleep -Seconds 2
   $quotes = Invoke-RestMethod "$api/products/$($p.id)/quotes"
   $quotes | Select-Object -First 3 kind, priceCents, currency, provider, observedAt | Format-Table -AutoSize
   ```
   **Look for:** at least one quote, observed seconds ago. No `POST /jobs/run-due` needed, no 30-second wait.
   (Only the `fixture` provider is active without a Best Buy key, so these prices are scaffolding, not market truth.)
2. Set what you paid for a part — pick one that now shows a current price:
   ```powershell
   $parts = Invoke-RestMethod "$api/parts"
   $target = $parts | Where-Object { $_.product.category -eq 'gpu' } | Select-Object -First 1
   Invoke-RestMethod -Method Patch "$api/parts/$($target.id)" -ContentType 'application/json' -Body '{"acquiredPriceCents":55000}'
   ```
   (**Integer cents** — 55000 is $550.00. `/` also has an inline edit for this; use whichever you prefer.)
3. Reload `/builds/{id}`. **Look for:** `Paid` moves by exactly what you entered, and `Δ` moves with it. **Exact to
   the cent** — money is integer minor units, so a one-cent drift is a real bug.
4. **The thing most likely to look wrong, and isn't:** `Δ` is **not** `Paid − Now`. The three numbers cover
   different sets of parts, and the caption underneath says so — *"Now covers 5 of 10 parts · delta over the 4
   parts with both a cost basis and a price"*. If those three ever do line up arithmetically it's a coincidence,
   not a rule. **Tell me if the caption doesn't make that land** — it's new wording and you're its first reader.
   (It now says "1 part", not "the 1 parts", when a count is one.)
5. **The `—` state, and a known gap.** A part that has *never* had a cost basis already shows `—` (not `$0.00`) and
   stays out of the Δ set — the fresh import in §1 is full of them, and §6 step 3 checks it on a clean container.
   **You cannot currently clear a cost basis once set:** `PATCH …/parts/{id}` with `{"acquiredPriceCents":null}`
   returns **400** `invalid_request` ("expected number, received null"). The PM hit this running this guide; it is
   a real M0 gap, logged for the architect, not something you're doing wrong. To get back to `—` today, reset the
   dev DB (§0) or delete and re-create the part.

## 3. Share a build as a URL — and get it into Discord

Pillar 3 — the PCPartPicker bar.

1. From `/builds`, open a build, then open its share page: `http://localhost:5173/b/<slug>`.
2. **Look for:** name, one row per part in **PC-part order** (CPU, motherboard, memory, storage, video card,
   monitor…), spelled-out category names, prices (or `—`), and the Paid/Now/Δ block with its caption.
   **No serial numbers, no notes, no "acquired from", no owner name.** A serial on this page is a stop-the-line bug.
3. **No-JS check:** DevTools → Settings → Debugger → "Disable JavaScript", reload. **Look for:** the page still
   renders completely, and **Download card** is still there as a plain link. The **Copy card image** and **Copy
   Markdown** buttons disappearing without JS is intended.
4. **Discord.** Two facts to keep straight:
   - **Discord will not unfurl `localhost`** — its servers can't reach your box. Pasting the URL into a DM gets you
     a plain link until this is hosted somewhere public.
   - **Discord does not render Markdown tables at all.** Don't paste the Markdown export there (that's for Reddit
     and forums — §4). This was F13.
   So, for Discord today: click **Copy card image** on the share page, then paste (Ctrl+V) straight into the Discord
   message box. **Look for:** the PNG card appears as an attachment preview. If the button reports a failure (some
   browsers don't allow image clipboard writes — Firefox notably), use **Download card** and drag the file in.
5. **Look at the card itself:** name not clipped; up to 8 rows plus "+N more"; per-item prices or `—`; the
   Paid/Now/Δ footer with Δ coloured; the caption fully visible with space beneath it.
6. **Edge case — private:** `PATCH /api/v1/builds/{id}` with `{"visibility":"private"}` (from `/api/docs`), then
   reload `/b/<slug>`. **Look for:** a 404 page — not an error dump, not the build. Set it back to `unlisted`.

## 4. "Copy Markdown" → paste into Reddit

1. On the share page, click **Copy Markdown**.
2. Paste into a Reddit comment box and hit **Preview** (any Markdown previewer works — **not** Discord, see §3).
3. **Look for:** a clean `Type | Item | Price` table, one row per part, readable type names ("Video Card", not
   `gpu`), the Paid/Now/Δ rows, the italic caption, and a "Generated by" footer whose link is
   `http://localhost:5173/b/<slug>` — **a page a human can open**, not `http://api:3000/api/v1/…` (that was F10).
4. **Edge case:** a build with one item, and a part whose model contains a `|`.

## 5. Manual entry and build editing

These endpoints are the fallback when capture can't reach something.

1. `/builds/{id}` → **add a part** to a build, then **remove** it. Works with JS disabled (plain form posts).
2. **Edge case:** add a part that's already in **another** build. **Look for:** a readable message naming the build
   it's already in — not a raw 502.
3. **Edge case:** delete a part that's in a build via `/api/docs` (`DELETE /api/v1/parts/{id}`). **Look for:** a
   **409** refusing it; retry with `?force=1` and it succeeds.
4. `DELETE /api/v1/builds/{id}` on a throwaway build. **Look for:** the build is gone and **its parts still exist**,
   now `on_shelf`. Deleting a build must never delete hardware you own.

## 6. `docker compose up` — the deployment story

Stop `pnpm dev` first (Ctrl+C in that terminal) so nothing is holding a port.

```powershell
docker compose down -v      # start from nothing — removes the pcpi-data volume
docker compose up --build
```

1. **Look for:** both containers start, `api` reports healthy, and the log shows migrations running against an
   empty database. The containers publish **3000** (api) and **5173** (web) — the dev-mode `3010` doesn't apply here.
2. Import the fixture (the container's DB is empty, exactly like §0's):
   ```powershell
   curl.exe -s -X POST http://localhost:3000/api/v1/imports/scans -H "Content-Type: application/json" --data-binary "@tools/scanner/fixtures/MOONPC.redacted.json"
   ```
3. Open `http://localhost:5173/` and `http://localhost:5173/b/<slug>`. **Look for:** the same pages as dev mode,
   and — with no cost basis set in this fresh DB — `Paid —`, not `Paid $0.00`.
4. **The unfurl path specifically** — this is the URL Discord fetches:
   ```powershell
   curl.exe -s -o card.png -w "%{http_code} %{content_type}`n" http://localhost:5173/api/v1/share/<slug>/card.png
   ```
   **Look for:** `200 image/png`. Anything else means the share card won't unfurl. (Delete `card.png` afterwards.)
5. Check the Markdown footer through the container, where the old bug lived:
   ```powershell
   $md = Invoke-RestMethod "http://localhost:5173/api/v1/share/<slug>.md"
   $md -split "`n" | Select-String 'Generated by'
   ```
   **Look for:** `http://localhost:5173/b/<slug>`. Seeing `api:3000` or `/api/v1/` here is F10 come back.
6. `docker compose restart api`, reload the share page. **Look for:** the data survived — it's on a named volume.
7. `docker compose down` when finished. **Look for:** no stray node processes, no held ports.
8. *Note:* the images are large (~717 MB api, ~592 MB web). Known, deliberate for M0, with a slimming work item
   queued for M1.

## 7. What to report back

Per section: what you did, what you saw, and anything that felt wrong even if nothing errored. Especially:

- Any serial, note, "acquired from" or owner name on a share page, in the Markdown, or on the card.
- Any money figure off by a cent, or a Δ whose sign looks wrong. Any `$0.00` where you expected `—`, or vice versa.
- Whether the **Paid / Now / Δ caption** actually explains why the three don't add up.
- Whether **Copy card image** worked in your browser, and what the paste looked like in Discord.
- A scan that takes more than a few seconds, or reports hardware you don't have.
- Anything that looks bad at phone width, or a card that clips.
- Anything you had to guess at — that's a docs bug, and the cheapest kind to fix.

## Known limits in M0 (not bugs)

- One owner (`local`), no auth UI. `API_TOKEN` is unset in dev and compose, so mutating routes are open.
- Only the `fixture` pricing provider is active without a Best Buy key — prices are scaffolding, not market truth.
  `GET /api/v1/providers` shows `bestbuy` as `configured: false`.
- Cost basis is manual. Order-history import and barcode capture are M1.
- Builds hold owned parts only — no wishlist items (D9).
- Postgres is a compose stub, not exercised (M2). The scanner is Windows-only (M1 decides the cross-platform path).
- `POST /api/v1/jobs/run-due` returns **404** in the container by design (D10 — dev/harness only). Under `pnpm dev`
  it now works, and you shouldn't need it: enqueuing a refresh runs it immediately (D18).
- Parts imported *before* this fix-up keep their old identity key (that trailing `.`). Not migrated on purpose —
  the dev DB is disposable; §0 tells you to delete it.
- **A cost basis can be set but not cleared** (`{"acquiredPriceCents":null}` → 400). Found by the PM running this
  guide; flagged to the architect as a gap, not scheduled here.
- `PUBLIC_ORIGIN` has no sensible default under `pnpm dev`, so §0's recipe sets it by hand. Compose sets it for
  itself. If you ever run the API without it, the Markdown footer will point at the API's own port.
- CI has never run: nothing has been pushed. That's the one piece of M0's done-definition still open.
