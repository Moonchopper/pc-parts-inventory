## 1. Scan a **second** machine and watch it become a build

This is the pillar-1 test: capture is automated, not typed. The scan on MOONPC is already the committed fixture;
this step proves the scanner works on hardware nobody developed against.

1. Start the API and web in dev mode:
   ```powershell
   pnpm dev
   ```
   Expected: API on `http://localhost:3000` (Scalar docs at `http://localhost:3000/api/docs`), web on
   `http://localhost:5173`.
2. On the **second** Windows machine (copy `tools\scanner\` to it, or run it over a share):
   ```powershell
   powershell -NoProfile -File tools\scanner\scan.ps1 -OutFile scan.json -Pretty
   ```
   - Open `scan.json`. **Look for:** `schemaVersion: 1`; `host.hostname` is that machine's name; one component
     per real part; `manufacturer`/`model` read like a human wrote them (no `Corporation`, no `(TM)`, no trailing
     spaces); serials present where the hardware exposes them and `null` — never `"Default string"` or
     `"To Be Filled By O.E.M."` — where it does not.
   - **Edge case to try:** a laptop or a headless box with no monitor attached. The scanner must warn and skip
     the monitor category, not abort.
3. Send it to the API (from the second machine, pointing at your dev box, or copy the file back and post it):
   ```powershell
   powershell -NoProfile -File tools\scanner\scan.ps1 -ApiUrl http://<devbox>:3000
   ```
   Expected: an HTTP 201 and a printed `summary` with `productsCreated`, `partsCreated`, `buildId`.
4. Open `http://localhost:5173/builds`. **Look for:** a new build named after that machine's hostname.
5. **Re-run the same scan** (step 3) and refresh `/builds`. **Look for:** *no* duplicate build and *no* duplicate
   parts — the response should be a 200 (replay), not a 201. This is D8, idempotent import.
6. **Edge case:** physically remove or disable a part on that machine (unplug a monitor is easiest), re-scan, and
   look at `/` (inventory). **Look for:** the missing part still exists with status `on_shelf` — never deleted.

## 2. Share a build as a URL, and paste it into Discord

This is the bar PCPartPicker sets (pillar 3).

1. From `/builds`, open a build, copy its share URL: `http://localhost:5173/b/<slug>`.
2. Open that URL in a browser. **Look for:** build name, one row per part, current value and delta, and nothing
   private — **no serial numbers, no notes, no "acquired from", no owner name**. If you see a serial on this
   page, that is a **stop-the-line bug**.
3. **No-JS check:** in DevTools → Settings → Debugger, tick "Disable JavaScript", reload. **Look for:** the page
   still renders completely. (The "copy Markdown" button may become a plain link — that is intended.)
4. **Unfurl check:** paste the URL into a Discord channel (a DM to yourself is fine).
   - **Look for:** a large card image with the build name and the paid-vs-now numbers, plus title and description.
   - *Note:* Discord must be able to reach the URL. `localhost` will **not** unfurl. Either run the compose stack
     with a tunnel, or paste the URL into a local OG-tag previewer, or view
     `http://localhost:3000/api/v1/share/<slug>/card.png` directly and confirm the image is what you would want
     Discord to show. Say which you did.
   - **Look at the card:** name not clipped, up to 8 item rows legible, the delta line has the right sign and
     colour, nothing overlapping.
5. **Edge case:** set a build's visibility to `private` (via `PATCH /api/v1/builds/{id}` in the Scalar docs at
   `/api/docs`) and reload `/b/<slug>`. **Look for:** a 404 page, not an error dump and not the build.

## 3. "Copy Markdown" → paste into a Reddit comment

1. On `/b/<slug>`, click **Copy Markdown**.
2. Paste into Reddit's comment box and hit **Preview** (or any Markdown previewer).
3. **Look for:** a clean `Type | Item | Price` table, one row per part, readable category names ("Video Card",
   not `gpu`), a totals block, and the "Generated by" footer. Nothing should render as a broken table because of
   an unescaped `|` in a product name.
4. **Edge case:** a build with a single item, and a build with a part whose model contains a `|` or a very long
   name.

## 4. Change what you paid → the delta changes

This is pillar 2 (paid-vs-now) end to end.

1. On `/` (inventory), find a part with a current price. Note its **acquired**, **current** and **delta**.
2. Edit its acquired price — through the UI if the build page exposes it, otherwise
   `PATCH /api/v1/parts/{id}` with `{"acquiredPriceCents": 12345}` from `/api/docs`.
3. Reload `/builds/<id>`. **Look for:** the build's `acquired` total moved by exactly the amount you changed and
   the delta moved with it, in the opposite direction. **The numbers must be exact to the cent** — money is
   integer minor units (D6); a rounding drift of a cent is a bug worth reporting.
4. **Edge case:** clear the acquired price entirely (set it to null). **Look for:** the row shows "—" rather than
   `$0.00`, and the build total excludes it rather than treating it as free.

## 5. Price refresh records history

1. `POST /api/v1/products/{id}/refresh` from `/api/docs`. Expected: **202** with a `jobId`.
2. Wait ~30 s (the tick loop), then `GET /api/v1/products/{id}/quotes`.
3. **Look for:** a new quote row, newest first, with its `kind` (`new_retail` / `used_market` / `msrp`) and
   `observedAt`. Refresh again later and confirm the **old row is still there** — `price_quotes` is append-only
   (D5); a refresh must never overwrite history.
4. *Note:* with no `BESTBUY_API_KEY` set, only the `fixture` provider is active — `GET /api/v1/providers` should
   show `bestbuy` as `configured: false`. That is the expected state.

## 6. `docker compose up` cold start

The deployment story (D13/R2). Run this **after** stopping `pnpm dev` so the ports are free.

```powershell
docker compose down -v      # start from nothing: removes the pcpi-data volume
docker compose up --build
```

1. **Look for:** both containers start; `api` reports healthy; the API log shows migrations running and the
   `local` owner being seeded on an empty database.
2. Import the real fixture:
   ```powershell
   curl.exe -s -X POST http://localhost:3000/api/v1/imports/scans -H "Content-Type: application/json" --data-binary "@tools/scanner/fixtures/MOONPC.redacted.json"
   ```
3. Open `http://localhost:5173/` and `http://localhost:5173/b/<slug>`. **Look for:** the same pages you saw in
   dev mode, served from the containers.
4. `docker compose restart api`, then reload the share page. **Look for:** the data survived — it lives on the
   named volume, not in the container.
5. `docker compose down` when you are done. **Look for:** no stray node processes and no leftover port binds.

## 7. What to report back

For each section: what you did, what you saw, and anything that felt wrong even if nothing errored. Specifically
worth flagging:

- Any serial, note, "acquired from" or owner name visible on a share page, in the Markdown, or on the PNG card.
- Any money figure that is off by a cent, or a delta whose sign is wrong.
- A scan that takes more than a few seconds, or one that reports hardware you do not have.
- Anything on the share page that looks bad at phone width, or a card that clips.
- Anything you had to guess at — that is a docs bug, and it is the cheapest kind to fix.

## Known limits in M0 (not bugs)

- One owner (`local`), no auth UI. `API_TOKEN` is unset in dev and in compose, so mutating routes are open.
- Only the `fixture` pricing provider is active without a Best Buy key; prices are scaffolding, not market truth.
- Builds hold owned parts only — no wishlist/planned items (D9).
- Postgres is a compose stub, not exercised (M2). No order-history import, no barcode (M1).
- The scanner is Windows-only (ADR-0001 § Consequences; M1 decides the cross-platform path).
