### The seven gotchas this data proves
1. **Trailing whitespace is everywhere** (`Name`, `PartNumber`, monitor `UserFriendlyName`). Trim every string,
   and collapse internal runs of spaces in CPU names.
2. **Placeholder serials.** `"Default string"`, `"To Be Filled By O.E.M."`, `"None"`, `"System Serial Number"`,
   `"0"`, `""`, all-zero strings → emit `null`, never the placeholder. Build one `Clean-Serial` helper and use it
   for every class.
3. **`DeviceLocator` is NOT unique** — both sticks report `"DIMM 1"` on this board. `slot` is informational only;
   never assume it disambiguates. Include `BankLabel` in `specs` when present so a human can tell them apart, and
   let the serial carry identity (D8).
4. **`Win32_VideoController.AdapterRAM` is a uint32 and wraps** — the RTX 4070 Ti SUPER (16 GB) reports
   `4293918720`. Do **not** publish that as `vramMB`. Read the true size from the registry instead:
   `HKLM:\SYSTEM\CurrentControlSet\Control\Class\{4d36e968-e325-11ce-bfc1-08002be10318}\<0000..>` →
   `HardwareInformation.qwMemorySize` (QWORD), matched to the adapter by its `MatchingDeviceId`/`DriverDesc`.
   If you cannot match it reliably, **omit `vramMB` rather than emit a wrong number** and say so in your report —
   "documented-not-fixed" is a valid outcome (playbook learning 4).
5. **Integrated GPUs.** `"AMD Radeon(TM) Graphics"` is the 9800X3D's iGPU. Emit it as a `gpu` component (it *is*
   hardware you own) — do not filter it, but do strip `(TM)`/`(R)`.
6. **Enum ints need mapping.** `MSFT_PhysicalDisk.BusType` (17 = NVMe, 11 = SATA, 7 = USB, 8 = RAID, 10 = SAS),
   `MediaType` (3 = HDD, 4 = SSD, 5 = SCM, 0/1 = Unspecified). `Win32_PhysicalMemory.FormFactor` (8 = DIMM,
   12 = SODIMM), `SMBIOSMemoryType` (26 = DDR4, 34 = DDR5, 24 = DDR3). Emit the **string** in `specs`.
7. **Monitor fields are `uint16[]`, zero-terminated**, and `ManufacturerName` is a 3-letter PNP ID
   (`ACR`→Acer, `DEL`→Dell, `BNQ`→BenQ, `SAM`→Samsung, `GSM`→LG, `AUS`→ASUS, `MSI`→MSI, `HWP`→HP, `LEN`→Lenovo,
   `VSC`→ViewSonic, `AOC`→AOC, `GBT`→Gigabyte, `ACI`→Asus). Decode with a small table and fall back to the raw
   3-letter code when unknown. Width/height come from `WmiMonitorBasicDisplayParams` (cm) or the current mode —
   `widthPx`/`heightPx` are optional; omit rather than guess.

Manufacturer cleanup targets seen here: `"Gigabyte Technology Co., Ltd."` → `Gigabyte`,
`"American Megatrends International, LLC."` → `American Megatrends`, `"AMD Radeon(TM) Graphics"` → manufacturer
`AMD`, model `Radeon Graphics`. Strip `Corporation`, `Corp.`, `Inc.`, `Ltd.`, `LLC`, `Co.`, `(R)`, `(TM)`, `™`,
trailing commas and whitespace.

## Contracts

Emit **exactly** `docs/milestones/M0-seed.md` §4 ScanPayload v1:
```
ScanComponent = { category, manufacturer, model, partNumber?, serial? (string|null), quantity? (default 1),
                  slot?, specs: Record<string, string|number|boolean|null> }
ScanPayload   = { schemaVersion: 1,
                  scanner: { name: string, version: string, os: 'windows'|'macos'|'linux' },
                  host:    { hostname: string, scannedAt: ISO-8601 string },
                  components: ScanComponent[] }
```
`category` must be one of §3's enum: `cpu, cpu_cooler, motherboard, memory, storage, gpu, case, psu, case_fan,
monitor, os, keyboard, mouse, headset, other`. `specs` keys per §4: cpu `cores, threads, maxClockMHz, socket`;
gpu `vramMB, driverVersion`; memory `capacityMB, speedMT, formFactor`; storage `capacityBytes, bus, mediaType,
firmware`; motherboard `biosVersion, chipset`; monitor `widthPx, heightPx, manufactureYear`. All optional — emit
what the OS actually exposes, never a guess. Extra keys are allowed but keep them few and typed as
string/number/boolean/null (no nested objects, no arrays).

Emit UTF-8 **without BOM** and with ISO-8601 UTC `scannedAt` (`(Get-Date).ToUniversalTime().ToString('o')`).
`scanner.name = "scan.ps1"`, `scanner.version` a semver string you bump, `scanner.os = "windows"`.
Numbers must be JSON numbers, not strings. `-Depth 6` or more on `ConvertTo-Json` (5.1 defaults to 2 and will
silently stringify your objects — this is the classic 5.1 trap).

**If a contract must change, escalate. Do not adjust it.**

## Deliverables
1. **`ScanLib.ps1`** — pure functions, no CIM calls, so they are testable without hardware:
   `Clean-String`, `Clean-Serial`, `Clean-Manufacturer`, `Split-VideoName` (→ manufacturer + model),
   `Get-JedecManufacturer` (numeric JEDEC id → name, for boards that report a number instead of `"G.SKILL"`),
   `ConvertFrom-Uint16Array` (monitor fields), `Get-PnpVendorName`, `Get-BusTypeName`, `Get-MediaTypeName`,
   `Get-FormFactorName`, `Get-MemoryTypeName`, `Get-SerialHash` (`sha256(serial)` hex, **first 12 chars**, via
   `[System.Security.Cryptography.SHA256]::Create()` — available in 5.1).
2. **`scan.ps1`** — params `-OutFile <path>`, `-ApiUrl <url>`, `-Token <string>`, `-RedactSerials`, `-Pretty`,
   `-SelfTest`. Behaviour:
   - builds the ScanPayload from the CIM classes in Recon,
   - `-RedactSerials` replaces every non-null `serial` with `Get-SerialHash` **before** writing or posting
     (and does the same for any serial-ish value inside `specs`),
   - `-OutFile` writes the JSON (UTF-8 no BOM); with no `-OutFile` it writes to stdout,
   - `-ApiUrl` POSTs to `<ApiUrl>/api/v1/imports/scans` with `Content-Type: application/json` and, when `-Token`
     is given, `Authorization: Bearer <token>`; prints the response status and the `summary`; **non-2xx ⇒ exit 1**,
   - `-SelfTest` runs the inline assertions (below) and exits 0/1 **without touching CIM or the network**,
   - `$ErrorActionPreference = 'Stop'`, `Set-StrictMode -Version 2.0`, a non-zero exit on any failure, and a
     `-WhatIf`-free, side-effect-free run when only `-OutFile` is given.
   - Every CIM call wrapped so that a missing class (e.g. `WmiMonitorID` on a headless box) **warns and skips
     that category** rather than aborting the scan.
3. **Tests.** `ScanLib.Tests.ps1` with Pester if `Get-Module -ListAvailable Pester` finds it; **and** a
   `-SelfTest` switch in `scan.ps1` with inline assertions that always works (5.1 ships no Pester by default —
   check and report which path you used). Cover at minimum: trailing-whitespace trim, each placeholder serial →
   `null`, `(R)`/`(TM)`/`Corporation`/`Ltd.` stripping, uint16-array decode incl. the 0 terminator, JEDEC id
   lookup, PNP vendor lookup, bus/media/formfactor/memory-type mapping, and `Get-SerialHash` determinism +
   12-char length + **not equal to the input**.
4. **The real fixture.** Run
   `powershell -NoProfile -File tools/scanner/scan.ps1 -RedactSerials -Pretty -OutFile tools/scanner/fixtures/MOONPC.redacted.json`
   and **commit the result**. Open the file and confirm by eye that **no raw serial survives** (the four serials in
   the Recon block above are exactly what must NOT appear: `055D00F7`, `4859BDFA`,
   `0000_0000_0000_0001_00A0_7523_E87F_6C0C.`, `9K8H2S3`, `55F00669SL0`). Grep for them and paste the (empty) result.
5. **`tools/scanner/README.md`** — usage, the parameters, what is redacted, and the "run it on a second machine"
